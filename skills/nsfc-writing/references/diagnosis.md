# 诊断本子：症状、原因与改法

## 先核对材料

用户给出本地文件或目录时，先检查：正文引用的图片、附件路径是否存在；图号、式号、研究内容编号的交叉引用是否一致；研究内容之间的引用是否与编号顺序一致（反馈关系是否已标明）。

## 严重程度

- **致命**：足以否定全本。没有科学问题；论证链断裂；下列硬性违规。
- **严重**：明显扣分。结构缺失、对应关系错乱、证据强度与结论不符、夸大、正文超过 30 页上限。
- **一般**：语言、格式、细节；超出 skill 建议篇幅但未超上限。

每条问题写“位置—问题—为什么扣分—怎么改”。只报确实存在的问题；用户原文已经满足的要求不列。

## 硬性违规

- 删改提纲标题或括号文字。
- 参考文献检索不到（疑似编造）。
- 实验图、数据图来源不真实。
- 代表作虚标第一或通讯作者、夸大本人贡献。
- 研究基础中虚报项目主持或成果归属（他人主持的写成本人主持、团队成果计入个人）。

参考文献作者、期卷号等格式错误列为一般。

## 常见症状

| 症状 | 典型表现 | 根源 | 改法 |
|---|---|---|---|
| 任务流水线 | 研究内容是“制备—表征—试验—验证—规程”；进展是“某某研究了……”逐条罗列 | 没有假说，只有任务 | 先填工作表、写出假说，研究内容改为回答假说的子问题；进展按观点归类 |
| 看不出新意 | 读完说不出与别人有什么不同 | 新切入与科学本质的关系没写出来；创新是研究内容换个说法 | 写清新方法为什么能作用于科学本质；每条创新对应一个困难；写出申请人的条件 |
| 停在技术层 | 研究目标是“建平台、建规程、研发技术”；用词多为开发、优化、工艺 | 没拆到科学本质 | 找出指标背后的底层过程，目标改为阐明机制或建立可推广的关系；应用放到用途里 |
| 写成综述 | 立项依据讲整个领域的发展史 | 没有先定论证主线 | 只保留为本项目问题铺路的文献，每段末尾一句结论 |
| 缺口空泛 | “缺乏系统研究”“仍是黑箱”“机制尚不明确” | 没追问到具体环节 | 写出缺哪一环、为什么缺 |
| 前后脱节 | 立项依据列了很多不足，研究内容只处理其中一两个；技术细节与研究内容对不上 | 写完各部分没有对照 | 做对应表：问题→内容→目标→方案→创新→基础 |
| 编号倒挂 | 内容二使用内容三的结果，又没标为反馈 | 编号没按依赖关系排 | 按首次执行的依赖关系重排编号；迭代修正标为反馈 |
| 开头堆数据 | 研究内容或立项依据某段连列多项前期数字 | 把证据当主线 | 开头留一句定性判断，数字移到研究基础 |
| 证据过度解读 | 全局变化写成“已证实某位点作用”；相关写成因果；通用指标代替特异指标 | 结论超出数据 | 按数据实际能支撑的强度重写；缺的证据转为研究内容 |
| 防御性写作 | “需要说明的是”“与在研项目不重叠”“可能存在风险，将尽最大努力” | 把顾虑写进了正文 | 删除；与在研项目的区别写在项目情况栏，风险写在风险应对栏 |
| 口号与拔高 | 口号式小标题；“填补空白、国际领先” | 用情绪代替论证 | 小标题写结论；用证据说明价值 |
| 绝对断言 | “从未有人关注”“首次提出”“国内外空白” | 未检索就下结论 | 改为有限定的说法；给出中英文检索词，请申请人检索 |
| AI 腔 | 处处“全面、系统、深入”，项目符号列表，对仗排比，方案只说用什么 | 内容不具体 | 见 wording.md“去除 AI 腔” |
| 数字堆砌 | 摘要塞满百分比、样本量、发表数 | 证据和结论放错位置 | 摘要最多一个关键事实；证据放立项依据和研究基础 |
| 体量失衡 | 研究内容项数超出资助体量；某一项篇幅远超其他 | 选题未收窄 | 合并或删减，篇幅均衡 |
| 时态错误 | 研究方案写成“已经完成了……” | 把基础当计划 | 方案用将来时；已有结果移到研究基础 |
| 引用失效 | 图片路径不存在、图号跳号、正文所指与图不符 | 改稿后未同步 | 列出失效的引用与现有文件名，逐一对齐 |

“建立模型”本身不是毛病：模型表达了新的机制或可推广的定量关系，是科学贡献；只是为某个部门做预测工具，才属于停在技术层。

## 输出

1. 判断行。
2. 一句话总评：本子现在最大的问题是什么。
3. 问题清单（致命 → 严重 → 一般）。
4. 改写示例：挑问题最集中的一段改写，不编造文献，用【待补文献】占位。
5. 待核与待补。
