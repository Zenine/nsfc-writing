# 用往年结题报告做参考

## 去哪里找

国家自然科学基金基础研究知识库（kd.nsfc.cn）公开已结题项目的信息：项目名称、负责人、依托单位、批准年度、资助类别、申请时的摘要、结题摘要和结题报告全文。可以按关键词、申请代码、资助类别、年度检索。

查看结题报告全文需要先在网页上完成滑块验证。**滑块验证始终由用户本人完成**，agent 不尝试自动通过或绕过验证。用户问到如何获取时，按下面三种方式说明，推荐前两种：

**方式一：用浏览器自动化工具操作（推荐）**
agent 有浏览器操作能力时（如 Claude in Chrome、桌面版内置浏览器、browser-use、Playwright 等）：
1. agent 打开 kd.nsfc.cn，按用户给的关键词、申请代码、资助类别或年度检索，列出候选项目请用户挑选。
2. 打开选中项目的结题报告；出现滑块验证时停下，请用户在该浏览器窗口中亲手完成。
3. 验证通过后，agent 逐页保存报告页面图片到一个目录（文件名带页码），再用 `merge_pages.py` 合并。

**方式二：复制报告令牌，用脚本下载（推荐）**
1. 用户在自己的浏览器中打开结题报告并完成滑块验证。
2. 打开开发者工具的“网络”面板，找到发往 `/api/baseQuery/completeProjectReport` 的请求，复制请求参数中的 `reportToken`（必要时连同请求头里的 Cookie 和 User-Agent 一起复制）。网页前端设定令牌约 29 分钟后失效，拿到后尽快运行。
3. 运行 `python3 scripts/fetch_report.py --url "项目详情页地址" --token 报告令牌 --out 报告图片目录`（可加 `--cookie`、`--user-agent`）。脚本每页间隔不少于 1 秒、一次只下一份报告；令牌失效即停止并提示重新验证，重跑同一命令会跳过已下载的页面。需要 requests。
4. 用 `merge_pages.py` 合并为 PDF。

**方式三：完全手动**
在浏览器中完成验证后，逐页保存页面图片（对页面图片右键另存为，或截图），每个项目一个目录、文件名带页码，再用 `merge_pages.py` 合并。

合并命令：`python3 scripts/merge_pages.py 报告图片目录 --name "项目名称"`（只处理本地文件，需要 Pillow）。得到 PDF 或图片目录后交给 agent 分析。

报告供个人学习参考，按网站使用条款使用；报告里有他人的姓名、单位和成果，留在本地私有目录，不放进公开仓库，不对外分发。

## 选哪些项目

- 同一申请代码、相同资助类别、近几年结题的项目。
- 研究对象或方法与本项目相近，但不必完全相同：看别人怎样把相近的问题收窄成一个项目。
- 每次挑三五个即可，宁精勿多。

## 读什么

| 看什么 | 用来判断 |
|---|---|
| 题目与申请时摘要 | 同类项目把问题收窄到什么程度；题目里放了哪些要素 |
| 申请时摘要与结题摘要的差别 | 计划与实际完成之间常见的落差，哪些承诺偏大 |
| 结题报告中的研究内容与完成情况 | 同类资助额度下实际做得完的体量 |
| 成果清单 | 量力承诺的参照：同类项目实际产出的论文、专利数量与类型 |
| 遇到的问题与调整 | 风险应对可以预先考虑哪些情况 |

## 不该怎么用

- 结题报告是事后总结，结构与申请书不同，不照搬其章节结构。
- 不照抄文字；借鉴的是收窄问题的方式和体量判断。
- 引用其中的研究结果，按正式发表的论文引用；没有正式发表的，不作为本项目的文献依据。
- 别人的成果不写进本项目的研究基础。

## agent 读报告时的输出

用户提供本地报告（PDF 或图片目录）后：

1. 逐份列出：项目名称、资助类别与年度、研究内容项数、关键科学问题（如报告中写明）、主要成果类型与数量。
2. 横向比较：与本项目在问题收窄程度、体量、方法上的异同。
3. 对本项目的具体建议，每条注明依据来自哪份报告的哪一部分。
4. 报告中看不清或缺页的部分标【待核】，不补写。
