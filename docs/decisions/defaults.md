# 默认值与理由

skill 中的经验默认值及其理由。与用户单位规定或本人决定冲突时，按后者执行。

| 事项 | 默认值 | 理由 |
|---|---|---|
| 题目 | 读一遍能说出对象、科学问题、方法；一行放得下 | 评审最先读题目，三样齐全才能判断项目方向与可行性 |
| 摘要长度 | 不超过系统限制，写完报告实际字数 | 超限无法提交；报告字数便于申请人核对 |
| 关键科学问题 | 以问号结尾的问句，问一个未知的机制或关系 | 问句迫使写作者说清“未知的是什么”；不提供填空模板 |
| 研究内容项数 | 由假说拆出的必要子问题决定：删掉任何一项假说就检验不了 | 项数按论证需要定，不按固定数目凑 |
| 研究内容编号 | 按首次执行的依赖关系编号，反馈另行标明 | 评审按编号阅读，倒挂会被读成逻辑错误 |
| 篇幅 | 按论证需要分配，合计不超过 30 页 | 研究方案要写得下每个要点的判据和备选做法 |
| 突出显示 | 全文一种方式，只突出整句结论 | 多种突出方式互相干扰，读者抓不住主线 |
| 研究期限 | 按信息系统生成 | 国自然研究期限由系统按项目类型生成，申请人不可改 |
| 补写的方法 | 可以写，逐条标“建议方法，待确认” | 方法是否可行只有申请人能判断 |
| 修改时缺假说 | 给三行小表，标“待申请人确认” | 科学问题由申请人决定，不能由 agent 悄悄定下 |
